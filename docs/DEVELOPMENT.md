# Developer notes

How to build, test and release the fix, and where things are. The technical log [WORKLOG.md](WORKLOG.md) (in Russian) explains every fix with its addresses; read it before you change `hogs.dll`.

## Build

You need Visual Studio 2022 or later with the C++ workload, CMake 3.20 or later and PowerShell 7 (`pwsh`). The game is 32-bit, so everything is built for Win32 with the static CRT: players need no Visual C++ redistributable.

```powershell
pwsh tools/make_release.ps1
```

The script:

1. Downloads `downloads/ogg-winmm_binary.zip` (ayuanx/ogg-winmm v2025.01.16) if it is not there, and checks its SHA-256.
2. Configures `build/` with `cmake -A Win32` if it is not configured.
3. Builds the Release `hogs.dll` and `ddraw.dll`.
4. Writes the player package `dist/HogsFix/` and `dist/HogsFix.zip`.

Only the DLLs: `cmake -S . -B build -A Win32` and then `cmake --build build --config Release`. The renderer call tracer is a separate target: `--target d3dtrace`.

To try a build in the game, install the package into it: `dist\HogsFix\patch.cmd -GameDir "<game folder>"`.

## Tests

`pwsh tools/test_patcher.ps1` runs the patcher from `dist/HogsFix` through about 100 checks: install, update from the previous release, restore, a hand-installed dgVoodoo, damaged `hogs.ini` files, odd folder names, a running game and more. It works on copies in a temporary folder and does not touch the game.

It needs files that are not in git: `backup/warhogs_.exe.orig` (the original Steam v1.2 exe), `backup/winmm.dll.ogg-winmm-2014` (the `winmm.dll` that comes with the game) and `downloads/dgVoodoo2_87_5.zip`. So it runs only on a developer machine, not on GitHub.

## Releases

[.github/workflows/build.yml](../.github/workflows/build.yml) runs `tools/make_release.ps1` on every push and pull request and attaches `HogsFix.zip` to the run as an artifact. A tag that starts with `v` also publishes a GitHub release with the zip and the text of [.github/release-notes.md](../.github/release-notes.md):

```powershell
git tag v1.0.0
git push origin v1.0.0
```

The README download links point to `releases/latest/download/HogsFix.zip`, so the zip keeps that name in every release.

| Path | Contents |
|---|---|
| `src/hogs/` | `hogs.dll`, the runtime fixes, and the `hogs.ini` template |
| `src/ddraw/` | `ddraw.dll` (hogsdraw), DirectDraw 7 and Direct3D 7 on Direct3D 11. `stubs.h` is generated by `tools/gen_com_stubs.py` |

| `patcher/` | The player patcher: `patch.cmd`, `uninstall.cmd`, `patch.ps1` and the exe patch `warhogs_v12.json` |
| `tools/` | Build, test and reverse-engineering scripts, see below |
| `docs/` | `WORKLOG.md` (technical log), `TODO.md` (tasks), `renderer/` (analysis of `_d3d.dll` and the DirectX 7 subset) |

Not in git (`.gitignore`): `build/`, `dist/`, `downloads/`, `backup/`, `work/` and the Ghidra project `ghidra/`.

### Tools

- `make_release.ps1`: the player package (see Build).
- `test_patcher.ps1` with `test_patcher_lib.ps1`: the patcher regression test.
- `crash_catch.ps1`: runs the game under a small debugger. It catches crashes with a stack, watches the display mode, tests Alt+Tab and takes window screenshots. Run it with the 32-bit Windows PowerShell.
- `dump.ps1`, `ll_table.py`, `ll_unwrap.py`, `make_patch.py`: remove LaserLock and build `patcher/warhogs_v12.json` (see below).
- `unmap_dump.py`: turns a memory dump of a module into a PE file that a disassembler can load.
- `gen_com_stubs.py`, `gen_d3dtrace.py`: code generators for `src/ddraw/stubs.h` and `src/d3dtrace/exports.h`.
- `peimp.py` lists the imports of PE files. `pesym.py` finds the nearest export of a DLL for an address.
- `unlock-windows.cmd` with `enable-windows.ps1`: turns the desktop windows back on after the unpatched game disabled them.

## Debugging

- `hogs.log` and `hogsdraw.log` are written next to the game. `hogs.log` has one line per fix: `ok`, or `skip` when the bytes do not match.
- Frame dump: add `[Debug]` with `FrameDump=1` to `hogs.ini`. F12 then writes the next frame to `hogsdraw_dump\`: every draw call with its caller address in `_d3d.dll`, the frame picture and its textures. `FrameDumpAt=N` also dumps frame number N by itself.

## Rebuilding the exe patch

`patcher/warhogs_v12.json` holds the SHA-256 of the original and of the patched `warhogs_.exe` and 326 changes: offsets with their old and new bytes, no game code. To rebuild it, start from the original exe. LaserLock decrypts itself in memory, so the dump must come from the unpatched game. Scripts marked "Run under 32-bit Windows PowerShell" need `C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe`.

```powershell
$repo = "<this repository>"
$game = "<game folder>"
# 1. Dump the running original game.
& C:\Windows\SysWOW64\WindowsPowerShell\v1.0\powershell.exe -File "$repo\tools\dump.ps1" -Exe "$game\warhogs_.exe" -OutDir "$repo\work\dumps"
# 2. The LaserLock table, and the exe without LaserLock.
python -I "$repo\tools\ll_table.py" "$repo\work\dumps\wh32lib.dll_10000000.bin" "$repo\work\dumps\warhogs_.exe_00400000.bin" "$repo\work\ll_table.json"
python -I "$repo\tools\ll_unwrap.py" "$repo\backup\warhogs_.exe.orig" "$repo\work\ll_table.json" "$repo\work\warhogs_unwrapped.exe" "$repo\work\ll_sites.json"
# 3. The patch description for the patcher.
python -I "$repo\tools\make_patch.py" "$repo\backup\warhogs_.exe.orig" "$repo\work\warhogs_unwrapped.exe" "$repo\work\ll_sites.json" "$repo\patcher\warhogs_v12.json"
```
